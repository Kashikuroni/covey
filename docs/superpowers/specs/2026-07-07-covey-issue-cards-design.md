# Слайс 29 — issue-карточки и WIP-сигналы (Design Spec)

> Строки списка issues становятся карточками в анатомии сессионных
> (фон card, рамка, полоска слева, тень), с лейблами, автором,
> возрастом и превью тела. Карточка показывает, что по issue уже
> ведётся работа: живая covey-сессия, локальная ветка, связанный PR.
> `g` — прыжок в сессию. База: ветка `slice-28` (слайс 28 не смержен).

## 0. Назначение

Список issues читается взглядом как список сессий, и сразу видно,
за какие issues уже взялись — сессия/ветка/PR — без похода в детали
или на GitHub. `g` замыкает цикл «issue → работа» в одну клавишу.

## 1. Данные

- `issueListFields` += `closedByPullRequestsReferences` — тот же
  единственный `gh issue list --json` вызов, без новых запросов.
- `GhIssue.linkedPRs: [GhPRRef]`; `GhPRRef: Decodable, Equatable`
  { `number: Int`, `url: String` }. Декод через `decodeIfPresent`,
  отсутствие ключа → `[]` (старые фикстуры живут).
- `IssueBrowserModel`:
  - `localBranches: [String]` — наполняется при `open` и
    `refresh(force:)` рядом с fetch issues;
  - инжект `fetchBranches: (String) async -> [String]` (дефолт —
    пустой список; живая проводка в AppModel через существующий
    `gitInfo(dir).branches`, как NewSessionSheet).

## 2. Матчеры (чистые функции, IssueModels.swift)

- `sessionNameMatchesIssue(name:number:)` — имя равно `"#N"` или
  начинается с `"#N "` (конвенция session-from-issue). `#12` не
  матчит `#123`.
- `branchMatchesIssue(branch:number:)` — два правила, и только они:
  (а) при токенизации имени ветки по `/`, `-`, `_` какой-то токен
  равен `"N"`; (б) имя содержит `"#N"` c границей токена справа.
  Покрывает `12-fix`, `issue/12`, `fix-12`, `feat_12_x`; не матчит
  `112-fix`, `1234`, `fix-121`, `#123` для N=12.
- `relativeAge(from:to:) -> String` — `"5m"` / `"3h"` / `"2d"` /
  `"3w"`; порог секунд < 60 → `"now"`.
- Сессия issue = первая из `model.sessions` текущего root, чьё имя
  матчится (фильтр по root — в пейне; матчер чистый). Ветка — первая
  совпавшая из `localBranches`. PR — первый из `linkedPRs`.
- Бейджи вычисляются при рендере строки: сессии всегда живые, ничего
  не протухает и не кешируется.

## 3. Карточка (IssueCardView.swift)

Анатомия сессионной карточки: фон `tk.card` (`cardHover` у
выделенной), рамка `bd`/`bd3`, скругление `Tokens.r`, тень
(`shadowColor`/`shadowRadius`/`shadowY`), полоска слева 2pt.
Полоска: выделена → `tk.t1`; иначе открытый → `tk.ok` приглушённый;
закрытый → прозрачно. Точки состояния из старой строки нет.

Строки (пустые схлопываются):

1. `#N` (mono 13 medium, `tk.t3`) + заголовок (`tk.t1` у выделенной /
   `tk.t2`, lineLimit 1) + Spacer + возраст `relativeAge(updatedAt)`
   (mono 10, `tk.t4`).
2. Превью тела: первая непустая строка body, caption `tk.t4`,
   lineLimit 1. Пустое body — строки нет.
3. Лейблы: первые 3 капсулы (как в деталях) + `+N` при переполнении +
   Spacer + автор (caption `tk.t4`). Строка рендерится, если есть
   хотя бы один лейбл или непустой автор.
4. WIP-строка (только при хотя бы одном сигнале, mono 10):
   - `▸ <имя сессии>` — цвет статуса сессии (running/waiting/idle,
     как statusLabelColor в списке сессий); клик — прыжок в сессию;
   - `⎇ <ветка>` — `tk.t3`, первая совпавшая, lineLimit 1;
   - `⇄ #<PR>` — `tk.t3`.

Список остаётся ScrollView + j/k + scrollTo; меняется только рендер
строки (вертикальный зазор 4pt). Выделение больше не красит фон
`accent.opacity(0.2)` — его несёт карточка (cardHover + bd3 + полоска).

## 4. Клавиши и подсказки

- `g` в списке и деталях: у выделенного issue есть живая сессия →
  выбрать её и передать фокус терминалу (существующая механика
  enterTerminal). Нет сессии — no-op.
- Подсказки: `g session ↗` в StatusBar (detail-набор) и строка в
  HelpOverlay. Футер списка не меняется.

## 5. Тесты

- Матчеры: позитив/негатив (`#12` vs `#123`; `12-fix`, `issue/12`,
  `fix-12` vs `112-fix`, `1234`, `fix-121`).
- `relativeAge`: пороги now/m/h/d/w.
- Декод `closedByPullRequestsReferences` на фикстуре + отсутствие
  ключа → `[]`.
- Наполнение `localBranches` через инжектированный fetchBranches.
- UI-карточка — руками; полный прогон зелёный.

## 6. Вне скоупа

- GitHub linked branches (gh issue develop / GraphQL).
- Создание ветки из issue.
- Статусы PR (open/merged) на бейдже — только номер.
- Изменение деталей/редактора/композера.
